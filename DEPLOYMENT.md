## Deployment Strategy

Fully **$0/month** deployment using free tiers across all platforms:

| Component | Platform | Tier | Cost |
|-----------|----------|------|------|
| Frontend (React SPA) | Firebase Hosting | Free (Spark) | $0 |

## Step 1: Set Up External Services

### 1a. MongoDB Atlas (Free M0 Cluster)

1. Go to https://www.mongodb.com/atlas
2. Create free M0 cluster (AWS, us-east-1 recommended)
3. Create database user + whitelist `0.0.0.0/0` (allows Render/HF IPs)
4. Copy connection string: `mongodb+srv://user:pass@cluster.mongodb.net/mediaguard`

### 1b. Upstash Redis (Free Tier)

1. Go to https://upstash.com
2. Create Redis database (us-east-1, free tier)
3. Copy connection string: `rediss://default:xxx@xxx.upstash.io:6379`

### 1c. API Keys

- Groq: https://console.groq.com → API Keys → Create
- Gemini: https://aistudio.google.com → Get API Key

## Step 3: Deploy FastAPI ML Engine to Hugging Face Spaces

### 3a. Create a New Space

1. Go to https://huggingface.co/new-space
2. Configure:
   - **Space name**: `mediaguard-fastapi`
   - **SDK**: Docker
   - **Hardware**: CPU Basic (Free — 16GB RAM, 2 vCPU)
   - **Visibility**: Public (required for free tier) or Private (with HF Pro)

### 3b. Clone the Space Repository

```cmd
git lfs install
git clone https://huggingface.co/spaces/YOUR_USERNAME/mediaguard-fastapi
cd mediaguard-fastapi
```

### 3c. Create the Dockerfile for HF Spaces

Create a `Dockerfile` in the Space repo root:

```dockerfile
FROM python:3.11-slim

# System deps for OpenCV headless + FAISS + ffmpeg + Node.js
RUN apt-get update && apt-get install -y --no-install-recommends \
    libgl1 libglib2.0-0 ffmpeg curl git \
    && curl -fsSL https://deb.nodesource.com/setup_20.x | bash - \
    && apt-get install -y --no-install-recommends nodejs \
    && rm -rf /var/lib/apt/lists/*

# Create non-root user (HF Spaces requirement)
RUN useradd -m -u 1000 user

WORKDIR /app

COPY requirements.txt .

# CPU-only torch
RUN pip install --no-cache-dir torch \
    --index-url https://download.pytorch.org/whl/cpu

RUN pip install --no-cache-dir -r requirements.txt

# Install gdown for Google Drive downloads
RUN pip install --no-cache-dir gdown==5.2.0

# Copy application code
COPY . .

# Download best.pth from Google Drive at build time (cached in Docker layer)
RUN python -c "\
import gdown, os; \
drive_id = '1WqoulPa3UKY29EDGNRPS4S83eNdH0JNY'; \
output = '/app/best.pth'; \
print('Downloading best.pth from Google Drive...'); \
gdown.download(f'https://drive.google.com/uc?id={drive_id}', output, quiet=False); \
size = os.path.getsize(output) / 1e6; \
print(f'Done: {size:.0f}MB')"

# Generate CLIP ONNX from HuggingFace at build time
RUN python export_clip_onnx.py

# Pre-download CLIP ViT-B/32 weights (transformers cache)
RUN python -c "\
from transformers import CLIPProcessor, CLIPModel; \
import torch; \
CLIPModel.from_pretrained('openai/clip-vit-base-patch32', torch_dtype=torch.float16); \
CLIPProcessor.from_pretrained('openai/clip-vit-base-patch32'); \
print('CLIP ViT-B/32 cached in float16')"

ENV FORENSICS_MODEL_PATH=/app/best.pth
ENV CLIP_ONNX_PATH=/app/clip_vision.onnx
ENV PORT=7860
ENV NODE_ENV=production

EXPOSE 7860

RUN mkdir -p /app/assets/official /app/assets/suspects && \
    chmod -R 777 /app/assets

USER user

CMD ["python", "main.py"]
```

### 3d. Update main.py Port for HF Spaces

In your `main.py`, the uvicorn startup should respect the PORT env var. Check the bottom of `main.py`:

```python
if __name__ == "__main__":
    port = int(os.environ.get("PORT", 7860))
    uvicorn.run(app, host="0.0.0.0", port=port)
```

### 3e. Copy Backend Files to Space Repo

```cmd
REM Copy all backend source files (NOT model files — those download at build time)
xcopy /E /I /Y ..\Backend\agents agents\
copy ..\Backend\main.py .
copy ..\Backend\requirements.txt .
copy ..\Backend\export_clip_onnx.py .
copy ..\Backend\download_models.py .
mkdir assets\official
mkdir assets\suspects
copy ..\Backend\assets\suspects\spider_payload.json assets\suspects\
```

### 3f. Push Code (Models Download at Docker Build Time)

```cmd
git add .
git commit -m "Deploy MediaGuard FastAPI - models downloaded at build time"
git push
```

> **Note:** Models are NOT stored in the repo (HF free tier has 1GB LFS limit).
> Instead, the Dockerfile downloads `best.pth` from Google Drive and generates
> `clip_vision.onnx` from HuggingFace CLIP during the Docker build step.
> This gets cached in the Docker layer — only re-downloads if Dockerfile changes.
> First build takes ~15-20 min, subsequent builds are fast (cached layers).

In HF Spaces Settings → **Repository secrets**:

|-------------|-------|
| `GEMINI_API_KEY` | your_gemini_key |

## Handling Sleep & Cold Starts

### HF Spaces (FastAPI) — Sleeps after 48h idle

- Wake time: ~30-60 seconds (fast, models already in filesystem)
- To keep awake: HF Spaces has a built-in "pinning" option (Settings → Space sleeping → Disable)
- Or use UptimeRobot to ping every 30 minutes

### Render Free (Node.js) — Sleeps after 15 min idle

- Wake time: ~30 seconds
- The keepalive code in `app.js` pings itself every 14 minutes
- Add UptimeRobot monitor as backup

### Recommended: UptimeRobot (Free)

1. Go to https://uptimerobot.com (free plan: 50 monitors, 5-min intervals)
2. Add monitors:
   - `https://YOUR_USERNAME-mediaguard-fastapi.hf.space/health` (every 30 min)
   - `https://mediaguard-node.onrender.com/` (every 5 min)

## HF Spaces — Important Notes

### Public vs Private
- **Free tier**: Space must be **public** (your code is visible)
- **HF Pro ($9/mo)**: Private Spaces available
- Secrets (API keys, DB URIs) are still hidden even on public Spaces

### Custom Domain
- Not available on free tier
- You get: `https://YOUR_USERNAME-mediaguard-fastapi.hf.space`
- Works fine — just use this URL in your Node.js `FASTAPI_URL`

### Build & Deploy
- Push to the Space repo → auto-builds Docker image → deploys
- Build logs visible in Space page → "App" tab shows logs
- Rebuild: Settings → Factory Reboot

### Rate Limits
- Free tier has rate limits but they're generous for demo/hackathon use
- If you hit limits, add `X-Hf-Token` header in your Node.js → FastAPI calls (use your HF access token)

## Troubleshooting

### "Build failed" on HF Spaces
- Check Dockerfile syntax — HF requires port 7860
- Ensure `USER user` is at the end (HF requires non-root)
- Check build logs in the Space page

### "Service unavailable" on HF Space
- Space may be sleeping. First request wakes it (~30-60s)
- Check Space status at `https://huggingface.co/spaces/YOUR_USERNAME/mediaguard-fastapi`

### "Render service sleeping"
- Free tier sleeps after 15 min. UptimeRobot prevents this.
- First request after sleep takes ~30s

### "Socket.IO disconnects"
- Render supports WebSockets natively
- Ensure `CLIENT_URL` matches your Firebase URL exactly (including https)

### "YouTube downloads failing"
- Platform IPs may be blocked. Set cookies:
  1. Export YouTube cookies from browser
  2. Base64 encode: `certutil -encode cookies.txt cookies_b64.txt`
  3. Add as secret in HF Spaces: `YOUTUBE_COOKIES_B64`

### "Models not loading on HF Spaces"
- Models download during Docker build, not at runtime
- Check build logs for gdown/Drive download errors
- If Google Drive rate-limits the download, rebuild after a few minutes
- Verify `FORENSICS_MODEL_PATH=/app/best.pth` in env
- CLIP ONNX is generated from HuggingFace at build time (no external file needed)

### "CORS errors in browser"
- FastAPI already has `allow_origins=["*"]` — should work
- Ensure Node.js `CLIENT_URL` includes your Firebase domain
